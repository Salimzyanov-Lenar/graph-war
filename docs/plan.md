# План recreating-graphwar

Собственная упрощённая онлайн-игра Graphwar: пошаговые выстрелы графиком `y=f(x)` в локальных координатах бойца, случайные карты с неразрушаемыми круглыми препятствиями, три бойца у каждого игрока, дружественный огонь, минута на ход, затем аккаунты и Elo-лидерборд. Термины — [CONTEXT.md](../CONTEXT.md).

## Стек

**Backend (ты):** Go, `net/http` (chi при необходимости), `pgx/pgxpool` + `sqlc` + `goose`, PostgreSQL, WebSocket (`github.com/coder/websocket`), Argon2id и серверные cookie-сессии для аккаунтов. **Frontend (друг):** TypeScript + Vite + React; графика поля — PixiJS; тесты Vitest + Playwright. Обоснование и ловушки — в заметке `graphwar-stack-research.md` (кеш исследования, перенести в `docs/stack-research.md` при желании). Не добавлять заранее: Redis, ORM, физический движок, JWT.

## Главные правила совместной работы

1. **Сервер авторитетен.** Формулу проверяет, траекторию строит, столкновения и победу определяет Go. Клиент только отправляет `(fighterId, expression)` и воспроизводит присланные точки. Никакого повторного вычисления на TS.
2. **Блокировка — жёсткая.** Задача, у которой указано «Жёстко заблокирована: …», не начинается до закрытия всех перечисленных задач. Проверка готовности задачи — не «ИИ сказал, что готово», а перечисленные критерии.
3. **Параллель — через контракт и моки.** После согласования контракта (C01/C06) каждая сторона делает свои задачи на контрактных фикстурах и mock-транспорте, не дожидаясь кода другой стороны. Мок — только для разработки: E2E всегда против настоящего сервера.
4. **Совместные точки приёмки.** Ниже перечислены задачи **C** — они закрываются только вдвоём, в двух реальных браузерах. Задача бэка не считается принятой лишь потому, что её Go-тесты зелёные, если она входит в C-точку.
5. **Малые шаги.** Одна задача — один проверяемый результат. ИИ пишет код, вы читаете diff и запускаете проверки.
6. **Решения — через эксперименты.** Спорные технические вопросы оформлены в `.scratch/graphwar/` (карта решений): сначала маленький прототип/исследование и запись решения, потом задачи, которые от него зависят.

## Совместные точки приёмки (C)

<a id="c01"></a>
## C01 — Совместный контракт гостевой игры

Не начинать код интеграции, пока не согласованы: система координат поля и бойца, формула и границы численной модели (вход D01), структура snapshot и событий, streamId/sequence, контракт ошибок и requestId/expectedTurnId, длительность фазы воспроизведения, формат случайной карты. Результат — согласованное описание в репозитории; оба сверяют по нему фикстуры. Дождаться: D01 (минимум по численной модели).

<a id="c02"></a>
## C02 — Приёмка комнаты двумя браузерами

Совместная ручная проверка: два независимых браузера, гости, создание и join по ссылке, ready/unready, refresh сохраняет гостя, чужой Origin и третий участник отвергаются. Блокирует B11. Дождаться: B09, B10, F05.

<a id="c03"></a>
## C03 — Приёмка первого сетевого выстрела

Одинаковый shotId и траектория у обоих игроков, ошибка начала не отдаёт ход, обрыв принятого выстрела отдаёт, повтор fire не создаёт второй выстрел. Блокирует F09 и B12. Дождаться: B11, F08.

<a id="c04"></a>
## C04 — Приёмка полного матча

Матч до победы на случайной карте: три бойца, выбор стрелка, дружественный огонь, минута хода по серверным часам, три пропуска — поражение, сдача. Блокирует F12. Дождаться: F09, B12.

<a id="c05"></a>
## C05 — Гостевой MVP через интернет

Законченный гостевой матч через HTTPS-туннель с двух устройств/сетей: refresh, reconnect, таймаут, лимиты. Точка готовности первого этапа; после неё стартуют аккаунты. Дождаться: B14, F12.

<a id="c06"></a>
## C06 — Контракт аккаунтов и истории

Согласовать поля регистрации, различие логина и ника, ответы ошибок, поведение сессии при выходе/истечении, переход guest→account, несколько вкладок, состав истории. Блокирует B17, F13. Дождаться: C05.

<a id="c07"></a>
## C07 — Приёмка аккаунтов и сохранённых результатов

Регистрация → вход → матч → refresh → история; приватный результат сохранён один раз, гостевые матчи не меняют рейтинг. Блокирует B20/B21 и F16. Дождаться: B19, F15.

<a id="c08"></a>
## C08 — Приёмка рейтингового пути

Очередь → матч → ровно одно начисление → история → лидерборд; приватный матч Elo не меняет. Дождаться: B23, F20.

<a id="c09"></a>
## C09 — Разрешение публичного запуска

Отдельное решение владельцев: хостинг, домен, бюджет, восстановление пароля, копирование БД. Без него деплой не выполняется. Дождаться: B24, F21, D04.

## Отложенные идеи (не входят в первый онлайн)

Учебная песочница с предпросмотром траектории; реванш и переподключение к завершённым матчам; повторы/запись матчей; мобильная версия; кусочные функции и расширение языка формул; наблюдатели-зрители.
