# Контракт гостевой игры Graphwar

**Статус:** v0.2 — синхронизирована с контрактным слоем фронтенда (`frontend/src/contract/schemas.ts`, F03): стороны `A`/`B`, фаза `lobby`, стоп-причина `hit`, время в Unix-ms, опциональное поле версии `v` в конверте. Изменения — только через MR с подъёмом версии. Числа численной модели — из эксперимента D01 (`.scratch/graphwar/issues/01-numerical-model.md`, resolved).

Контракт фиксирует всё, что фронтенд и бэкенд обязаны трактовать одинаково. Термины — [../CONTEXT.md](../CONTEXT.md). Изменения контракта — только через MR с пометкой версии.

## 1. Мир и координаты

- Поле: прямоугольник **ширина 100 × высота 60** единиц. Начало координат — левый нижний угол, **y вверх**, x вправо.
- Экранные пиксели, devicePixelRatio и letterbox — забота фронтенда; сервер знает только мировые координаты.
- Стороны — **`"A"` и `"B"`** (строчные не допускаются). Игрок A стреляет слева направо (`dir = +1`), игрок B — справа налево (`dir = -1`).

### Локальные координаты стрелка

Выстрел считается в системе стреляющего бойца:

- `t >= 0` — расстояние от стрелка по горизонтали **в сторону соперника**;
- `X = X0 + dir * t`, где `dir = +1` для стрелка слева, `dir = -1` для стрелка справа;
- `Y = Y0 + f(t) - f(0)` — выстрел всегда начинается ровно у бойца; постоянное слагаемое формулы роли не играет (`x^2` и `x^2+5` — одинаковый выстрел).

Следствия, обязательные для справки в UI (F06): `ln(x)` не стартует (f(0) не определён), `ln(x+1)` стартует; аргументы тригонометрии — **радианы**; десятичный разделитель — точка.

## 2. Язык формул

Ограниченный математический язык; пользовательский код не исполняется.

- Элементы: числа, `x`, `pi`, `e`, скобки, бинарные `+ - * / ^`, унарные `+ -`, явное умножение, функции `sin cos sqrt abs ln exp`.
- Приоритеты: `^` — правоассоциативный и выше унарного минуса: `-x^2 = -(x^2)`. `2^3^2 = 512`.
- Запрещено: неявное умножение (`2x`, `2(x+1)` — ошибка), переменные кроме `x`, присваивания, вызовы не из списка, любые конструкции языка хоста.
- Ограничения входа (отвергаются до разбора): длина ≤ **100 символов**; ≤ **64 узлов** AST; глубина AST ≤ **16**. Глубина считается по дереву (скобки её не растут); плоская цепочка вида `1+1+…+1` имеет глубину, равную числу узлов, — цепочки длиннее ~16 элементов отклоняются по глубине.

### Спорная семантика (утверждено по D01)

| Выражение | Результат |
|---|---|
| `0^0` | `1` |
| отрицательное основание ^ дробная степень | ошибка области определения (NaN) |
| деление на 0, `ln(x<=0)`, `sqrt(x<0)`, переполнение `exp` | ошибка области определения / не-конечное значение |

## 3. Численная модель траектории (дискретная, авторитетна на сервере)

- Шаг: `t` увеличивается с шагом **0.5** единицы; максимум **400 отсчётов** на выстрел (покрывает 200 единиц пути).
- В каждом интервале между соседними отсчётами — **2 подпробы** (на 1/3 и 2/3 интервала).
- Стоп-причины выстрела:
  - `hit` — первое пересечение с препятствием или живым бойцом (кроме стрелка); траектория обрезается точно на точке столкновения; `destroyedFighterId` указывается, если сбит боец (детали — B05);
  - `out_of_field` — очередная точка вне поля (по x или по Y); последняя точка включается, чтобы фронт видел направление выхода;
  - `discontinuity` — подпроба/отсчёт дали не-конечное значение или `|f(t)-f(0)| > 1e6` (асимптота/переполнение); траектория заканчивается на **последней валидной** точке, через разрыв не соединяется;
  - `non_finite` — то же на самом отсчёте (обрыв до него);
  - `max_points` — бюджет отсчётов исчерпан.
- Семантика ошибок (согласовано в Q14):
  - **Отказ до принятия**: `f(0)` не существует/не конечен (`ln(x)`, `sin(1/x)`) или формула не парсится — выстрел **не принят, ход не тратится**, таймер продолжает идти;
  - **Обрыв принятого**: разрыв/не-конечность дальше по траектории или выход за поле — выстрел **принят, ход тратится**.
- **Известное ограничение дискретной модели**: особенность, более узкая, чем сетка проверки (~0.17 единицы, пример `1/(x-0.6)`), может быть пересечена без обнаружения. Это принимаемое поведение, как в оригинальной игре; сервер не обещает непрерывную математику.
- Детерминизм: одинаковый вход в одной версии движка даёт одинаковый результат (float64, фиксированный порядок вычислений).

## 4. Карта

- Сервер генерирует карту: границы, **3 бойца на игрока**, неподвижные неразрушаемые круглые препятствия `{x, y, r}`.
- Инварианты генератора (проверяются автоматически): бойцы не внутри препятствий и не на границе; минимальные расстояния спавн-спавн и спавн-препятствие ≥ **4** единицы; препятствия внутри поля.
- Клиент получает готовую геометрию; генерация карты из seed на клиенте запрещена. `mapSeed` и версия генератора передаются для диагностики.
- Детали качества — D02 (`.scratch/graphwar/issues/02-random-maps.md`), пока статус open.

## 5. Правила матча

- Три бойца у каждого игрока; позиции фиксированы на весь матч; перемещений нет.
- Ход: игрок выбирает **любого своего живого бойца** и делает один выстрел.
- ПервыйHit: траектория останавливается на первом пересечении с препятствием или **любым живым бойцом** (включая своих — дружественный огонь), кроме самого стрелка; убитые коллизий не создают. Одно попадание — один убитый.
- Побеждающий ход важнее любых лимитов; лимита числа ходов и автоматической ничьей за промахи **нет**.
- Ход = **60 секунд** по серверным часам (открытие хода шлёт `deadlineAt` + `serverTime`). 60 секунд принадлежат вводу, а не анимации предыдущего выстрела.
- Таймауты считаются **лично** по своим ходам: принятый выстрел сбрасывает серию; третий личный таймаут подряд — техническое поражение.
- Сдача — явное действие с подтверждением в UI.
- Сервер авторитетен: клиент не вычисляет траекторию, попадания, таймауты и победу.

## 6. Состояния матча

`lobby` → `active` → (`resolving` ↔ `active`)* → `finished`; в любой момент → `aborted`.

- `resolving` — сервер принял выстрел, клиенты показывают анимацию; длительность фазы фиксирована контрактом: **1200 мс** (предложение, утверждают оба); следующий ход открывается сервером по истечении фазы, подтверждение анимации от клиента не ждётся.
- `finished` — итог + причина: `team_wiped` | `surrender` | `timeout_streak` | `forfeit_disconnect`.
- `aborted` — победителя нет, результат не засчитывается: остановка сервера, обоюдное отсутствие и т.п. Не путать с ничьей — ничьих в текущих правилах не существует.

## 7. Идентичность и сессия (гостевой этап)

- `POST /api/guest` {displayName} → HttpOnly-cookie с непрозрачным токеном; сервер хранит соответствие токен↔guestId. Ник — отображаемое имя, не ключ личности.
- Refresh страницы сохраняет личность; подмена `guestId` в JSON бесполезна.
- Уникальность ников **не гарантируется**.

## 8. Транспорт

Единый origin. REST для комнат, WebSocket для матча.

### REST (гостевой этап)

```
POST /api/guest            {displayName} -> {guestId, displayName}
POST /api/rooms            -> {roomId, inviteId}
POST /api/rooms/{id}/join  {inviteId}
POST /api/rooms/{id}/ready {ready: bool}
DELETE /api/rooms/{id}     (выход)
```

### WebSocket

- Endpoint `/ws`; handshake авторизуется cookie, Origin проверяется allowlist'ом (точный scheme://host:port).
- Конверт каждого сообщения:
```json
{"v": 1, "type": "...", "streamId": "match:<id>", "seq": 42, "payload": {...}}
```
- `v` — версия протокола, сейчас `1`; поле опционально (для обратной совместимости), но если пришло и не совпало — сообщение отвергается.
- `seq` монотонна в рамках stream; повтор — игнорировать, разрыв — запросить resync, snapshot заменяет всё.
- Время (`deadlineAt`, `serverTime`) — **Unix epoch в миллисекундах** (число).
- Команды клиента: `room.ready`, `match.fire {matchId, expectedTurnId, fighterId, expression, requestId}`, `match.surrender {confirm: true}`.
- События сервера: `snapshot`, `room.changed`, `match.started`, `turn.opened {turnId, side?, fighterId?, deadlineAt, serverTime}`, `shot.resolved {shotId, turnId, points: [[x,y]...], stopReason, destroyedFighterId?}`, `match.finished {winnerSide?, reason}`, `error {code, message}`.
- Клиент в командах **не присылает** координаты, попадания, damage, winner — только `fighterId` и `expression`.
- Дедупликация: `requestId` в пределах участника и матча; повтор с тем же содержимым → прежний ответ, с иным содержимым → `error/duplicate_request`.
- Ошибочные коды: `bad_expression` (парсинг), `domain_error_at_start` (f(0)), `not_your_turn`, `unknown_fighter`, `dead_fighter`, `room_full`, `room_expired`, `unauthorized`, `rate_limited`, `duplicate_request`, `stale_turn` (не совпал `expectedTurnId`), `server_error`.

### Переподключение (B13/F10)

- Обрыв соединения: место сохраняется **60 секунд**, таймер хода идёт. Возврат → полный `snapshot` + при необходимости недоигранная анимация.
- Вторая вкладка: новое соединение заменяет старое управляющее.
- Grace истёк → техническое поражение отсутствующему (если соперник на связи); оба отсутствуют → `aborted`.

## 9. Что не входит в этот контракт (отложено)

Аккаунты/Elo-полевые форматы (C06), рейтинговая очередь (D03), учебный режим с предпросмотром, реванш, мобильная раскладка.
