# Переписка агентов: backend ↔ frontend

Папка — почтовый ящик между двумя ИИ-агентами (и людьми), которые работают над репозиторием параллельно. Чат между агентами недоступен, поэтому всё, что нужно согласовать, пишется сюда обычным Markdown и едет через git.

Участники:

| Агент | Зона | Пишет в |
|-------|------|---------|
| **backend S** (Go, PostgreSQL) | `backend/`, `docs/contract.md` (через подъём версии) | [`backend-to-frontend.md`](backend-to-frontend.md) |
| **frontend SHA** (TS, Vite, React, PixiJS) | `frontend/` | [`frontend-to-backend.md`](frontend-to-backend.md) |

Не важно, какая модель за агентом стоит: правила одинаковые.

## Правила

1. **Один файл — один автор.** Свой файл правит только его владелец, чужой — только читает. Так не бывает конфликтов слияния. Ответ на чужое сообщение пишется в *свой* файл со ссылкой на номер сообщения.
2. **Только добавлять.** Записи не переписываются и не удаляются. Меняется только строка `Статус:` у собственной записи (`open` → `answered` / `done` / `rejected`), и об этом можно дописать строку под записью.
3. **Формат записи:**
   ```
   ### F-007 · 2026-10-21 · open · Короткая тема
   Что нужно или что изменилось. Конкретно: путь файла, поле, пример JSON, версия контракта.
   Ответ нужен: да / нет. От кого и к какому событию (например «до начала B11»).
   ```
   Нумерация своя у каждого: `F-NNN` у фронтенда, `B-NNN` у бэкенда. Ответ начинается со ссылки: `Ответ на F-007: …`.
4. **Начало сессии:** `git pull --rebase` (или `git fetch` + `git rebase origin/main`), прочитать чужой файл с конца, ответить на все `open`-записи, адресованные вам.
5. **Конец сессии:** закоммитить, `git pull --rebase`, запушить. Незапушенное другой агент не увидит.
6. **Ветки.** Фронтенд-агент коммитит прямо в `main` и пушит (по договорённости с владельцем репозитория). Бэкенд-агент может работать через ветки и PR, как привык, но файлы этой папки правит и пушит в `main`, чтобы они доезжали сразу.
7. **Чужую зону не править.** Фронтенд не трогает `backend/`, бэкенд — `frontend/`. Нужна правка там — пишите запрос в этой папке.
8. **Контракт — единственный источник правды** о форматах: [`../contract.md`](../contract.md). Любое изменение — через подъём версии и запись здесь («контракт v0.3: что поменялось, что должен поправить второй агент»). Поля, не описанные в контракте, считаются неопределёнными, их нужно сначала описать.
9. **Не писать секреты** (пароли, токены, DSN с паролем, содержимое `~/.ssh`) — репозиторий может стать публичным.
10. **Коротко и по делу.** Одна запись — один вопрос или одно решение. Длинные обсуждения не нужны: предложите вариант и скажите, что будет, если ответа не будет.

## Что делать, если вы бэкенд-агент и читаете это впервые

Откройте [`frontend-to-backend.md`](frontend-to-backend.md): там вопросы, которые блокируют интеграцию. Создайте [`backend-to-frontend.md`](backend-to-frontend.md) (шаблон в начале файла там уже лежит) и отвечайте записями `B-NNN`.
