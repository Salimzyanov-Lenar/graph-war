## B01 — Подготовка: Сервис запускается одной документированной командой

**Статус:** DONE (MR #1 смержен)
**Блокируется:** Нет — можно начинать сразу.

**Результат:** Сервис запускается одной документированной командой; здоровье проверяется HTTP-запросом.

**Сделать:**
- [ ] Инициализировать Go-модуль, конфигурацию адреса и режима запуска через окружение; проверить реально установленную версию Go и зафиксировать поддерживаемую.
- [ ] Выбрать net/http; chi добавлять только если маршруты действительно становятся неудобны. Сделать liveness, структурированные логи через slog и корректное завершение по сигналу.
- [ ] Развести чистую игровую логику, HTTP/WS-транспорт и хранение данных. Не создавать универсальные репозитории и интерфейсы до появления конкретного потребителя.
- [ ] Добавить команды форматирования, go vet, go test и README с запуском. Файлы .env.example — без секретов.

**Готово, когда:**
- [ ] Запуск с валидной конфигурацией даёт успешный health-ответ; невалидная конфигурация завершает процесс с понятной ошибкой.
- [ ] go test ./... и go vet ./... проходят; остановка не оставляет фоновые горутины сервера.

**Передача / ожидание:** Фронтенд может параллельно делать F01. Запуск сервиса не требует PostgreSQL до B15.

## B02 — Математическое ядро: Формула превращается в ограниченное AST без исполнения пользовательского кода.

**Статус:** IN REVIEW (ветка `backend/b02-expression-parser`, стек на MR #3 — смержь #3 первым)
**Блокируется:** [C01](#c01) (другой файл — docs/plan.md#c01)

**Результат:** Формула превращается в ограниченное AST без исполнения пользовательского кода.

**Сделать:**
- [ ] Реализовать токены чисел, x, pi, e, скобок, явного умножения, + - * / ^ и разрешённых функций sin/cos/sqrt/abs/ln/exp. Зафиксировать grammar и позицию ошибки.
- [ ] Зафиксировать приоритеты: степень правоассоциативна; -x^2 означает -(x^2). Поддержать унарные знаки. Десятичный разделитель — точка, аргументы тригонометрии — радианы.
- [ ] Запретить неявное умножение, переменные кроме x, присваивания, доступ к свойствам, команды, циклы и вызов произвольных функций. Подключённая библиотека не должна расширять этот язык незаметно.

**Готово, когда:**
- [ ] Табличные тесты покрывают корректные выражения, вложенность, унарный минус, порядок операций, неизвестный идентификатор, пустой ввод и незакрытые скобки.
- [ ] Фаззинг произвольных строк не вызывает панику; превышение ограничений входа отвергается до дорогого разбора.

**Передача / ожидание:** Передать фронту коды и позиции ошибок. Не делать TS-парсер обязательным: математическая семантика принадлежит серверу.

## B03 — Математическое ядро: AST безопасно вычисляется в точке

**Статус:** IN REVIEW (ветка `backend/b03-evaluator`)
**Блокируется:** [B02](#b02); [D01](#d01) (другой файл — docs/plan.md#d01)

**Результат:** AST безопасно вычисляется в точке; работа и память ограничены.

**Сделать:**
- [ ] Сначала дождаться решения «Численная модель траектории и безопасные пределы»: закрепить пределы длины, узлов, глубины, вычислений и диапазона результата.
- [ ] Реализовать разрешённые операции на float64 и явные ошибки области определения, переполнения, деления на ноль, NaN и Infinity. Семантику спорных степеней взять из решения, а не из случайного поведения библиотеки.
- [ ] Проверять f(0) до принятия выстрела. Ошибка начала не тратит ход и не продлевает таймер.
- [ ] Ограничивать вычисление счётчиком операций и глубиной; дополнительно иметь контекст отмены. Один wall-clock timeout без проверок внутри вычислителя не ограничивает CPU.

**Готово, когда:**
- [ ] Покрыты ln(x), ln(x+1), sqrt(x), отрицательное основание с дробной степенью, нулевые знаменатели и переполнение exp.
- [ ] Большая или вредоносная формула быстро отвергается; лимиты проверяются тестами и измерением, а не обещанием «должно быть быстро».

**Передача / ожидание:** Выдать набор принятых и отвергнутых формул для справки F06. Предварительная валидация не возвращает будущую траекторию.

## B04 — Математическое ядро: Сервер строит конечную траекторию, начинающуюся у бойца.

**Статус:** IN REVIEW (ветка `backend/b04-trajectory`; контракт v0.2)
**Блокируется:** [B03](#b03)

**Результат:** Сервер строит конечную траекторию, начинающуюся у бойца.

**Сделать:**
- [ ] Использовать t>=0, X=X0+direction*t, Y=Y0+f(t)-f(0), direction=+1 слева и -1 справа. Вводимый пользователем x соответствует t.
- [ ] Реализовать численную политику D01: ограничение области, числа точек, обработки разрывов и больших изменений. Выход за поле, недопустимое значение после старта или исчерпание игрового численного бюджета завершают принятый выстрел.
- [ ] Возвращать причину остановки и пригодные для передачи конечные координаты. Не соединять через выявленный разрыв два независимых участка.
- [ ] Различать математическое исчерпание заданного бюджета и внутренний сбой сервера: внутренний сбой не превращать в поражение игрока.

**Готово, когда:**
- [ ] Проверить прямую, параболу, синус, постоянную функцию, обе стороны поля и совпадение формы x^2 с x^2+5.
- [ ] Покрыть полюс между отсчётами, резкий рост и границу поля; результаты соответствуют именно документированной дискретной модели, не обещанию точной непрерывной математики.
- [ ] Повтор одинакового входа в одной версии движка даёт одинаковый результат.

**Передача / ожидание:** Передать фронту фикстуры списка точек и причин остановки. Фронт не вычисляет эту траекторию заново.

## B05 — Математическое ядро: Выстрел останавливается в первой точке пересечения с препятствием или бойцом.

**Статус:** IN REVIEW (ветка `backend/b05-collisions`, стек на B04)
**Блокируется:** [B04](#b04)

**Результат:** Выстрел останавливается в первой точке пересечения с препятствием или бойцом.

**Сделать:**
- [ ] Проверять пересечение отрезков траектории с окружностями, а не только попадание отдельных отсчётов внутрь окружности.
- [ ] Выбрать самое раннее пересечение по порядку движения; обрезать последний сегмент точно на столкновении. Политика касания, радиуса выстрела и равных расстояний берётся из D01.
- [ ] Учитывать всех живых бойцов, включая своих, кроме самого стрелявшего. Убитые бойцы не создают коллизию. Остановиться после первого поражения.

**Готово, когда:**
- [ ] Есть тесты: касание, маленькое препятствие между двумя отсчётами, два препятствия на пути, свой боец перед врагом, исключение стрелка, мёртвый боец, промах.
- [ ] Одна команда никогда не уничтожает двух бойцов; результат не зависит от порядка объектов в коллекции.

**Передача / ожидание:** Это основа попаданий и геометрических проверок генератора. Ни PixiJS, ни отдельный физический движок не являются источником коллизий.

## B08 — Комната: Гость имеет неподделываемую серверную идентичность, не связанную с уникальностью

**Статус:** TODO
**Блокируется:** [B01](#b01); [C01](#c01) (другой файл — docs/plan.md#c01)

**Результат:** Гость имеет неподделываемую серверную идентичность, не связанную с уникальностью ника.

**Сделать:**
- [ ] Создать ограниченный endpoint гостевой сессии: проверить ник, выдать криптографически случайный непрозрачный токен в HttpOnly-cookie.
- [ ] Хранить соответствие токена и guestId на сервере; ник не использовать как ключ личности. Установить Path, SameSite, срок жизни; Secure обязателен при HTTPS, локальный HTTP — отдельный dev-режим.
- [ ] Обновление страницы сохраняет личность. Определить продление активной сессии, чтобы длинный матч не обрывался из-за скрытого срока жизни.
- [ ] Ограничить создание гостей и длину/символы ника; никогда не писать cookie в логи.

**Готово, когда:**
- [ ] Повторный запрос с cookie возвращает прежнего гостя; без cookie это другой гость.
- [ ] Подставленный guestId в JSON не даёт чужую личность; вредоносный ник не исполняется как HTML.
- [ ] У процесса есть очистка неактивных гостей и лимит памяти без удаления участников живого матча.

**Передача / ожидание:** Достаточно памяти одного процесса. После его перезапуска гостевой матч не восстанавливается — это согласованное ограничение.

**Передача / ожидание:** После B09 фронт может подключать HTTP комнаты. Серверная часть не ждёт готовой графики.
