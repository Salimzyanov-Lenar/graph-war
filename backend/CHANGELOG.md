# Changelog

Все заметные изменения backend описываются в этом файле.
Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [Unreleased]

### Added

- B09–B12: комнаты, `/ws`, матч и таймер хода (`internal/rooms`, `internal/api/rooms.go`, `ws.go`). Хаб с одним мьютексом и абстракцией часов (тесты на фейковых часах): создание комнаты и приглашения, join/ready/leave по REST, `/ws` со snapshot первым сообщением, per-stream `seq` без дыр, старт матча при двух «готов» (случайный seed → карта → матч, snapshot на `match:<id>`), `match.fire` с проверкой `expectedTurnId`, дедупликацией `requestId` и маппингом ошибок, один таймер хода 60 с и фаза resolving 1200 мс, 3 личных таймаута = техпоражение, `match.surrender`, grace 60 с при обрыве (форфейт или `aborted`), вторая связь того же гостя закрывает первую кодом 4001, медленный клиент отключается (4002). Гости без БД — в памяти (`MemGuestStore`); `GRAPHWAR_WS_ORIGINS`. Личность вкладки: `X-Session-Mode: tab` + Bearer/subprotocol (см. контракт §8, «Уточнения v0.3.1»). В `internal/game` добавлен `Match.Forfeit`. Зависимость `github.com/coder/websocket`.
- B08: гостевая идентичность `internal/api` — `POST /api/guest {displayName}`: криптослучайный токен 32 байта в HttpOnly/SameSite=Lax/Path=/ cookie (30 дней, обновляется при использовании), в БД хранится только SHA-256 токена (`migrations/00002_guests.sql`, sqlc), личность определяется cookie, а не телом запроса; повторный запрос с cookie возвращает того же гостя (200), без cookie — нового (201); валидация имени 1–24 символа после trim, контрольные символы отвергаются; лимит создания гостей 20/мин на IP с ограниченной памятью; уборщик удаляет гостей, неактивных 7 дней (раз в час), живые матчи не трогает. Конфиг `GRAPHWAR_COOKIE_SECURE` (Secure-атрибут за HTTPS). Тесты: единица на фейковом хранилище (повтор, подделка cookie, чужой guestId в теле, валидация имён, rate limit, границы памяти) + интеграция с реальной БД; живая проверка curl с cookie-jar.
- B07: машина состояний матча `internal/game/match.go` — фазы lobby/active/resolving/finished/aborted, монотонный `turnID` с проверкой `expectedTurnId`, валидация выстрела (только владелец хода, только его живой боец, только в active), максимум одно уничтожение за выстрел, проверка полного уничтожения команды → finished (winner определяется состоянием, не клиентом), фаза resolving 1200 мс с игнорированием преждевременных `AdvancePhase`, сдача/аборт, личные таймауты (3 подряд → техпоражение, принятый выстрел сбрасывает серию), результат неизменяем после завершения. Всё без сети/БД/часов: время инъекцией. Тесты: полный сценарий с уничтожением команды, дружественный огонь, 5 типов отказов без изменения состояния, 100 легальных промахов без ничьей, таймаут-серии, неизменяемость результата.
- B06: генератор карт `internal/game/mapgen.go` — воспроизводимость по seed (`rand.NewPCG`), зеркальные пары препятствий (поворот 180°), фиксированный зеркальный спавн 3+3 бойца, инварианты ValidateMap (границы, зазоры, спавн-клиренс), лимит попыток + запасная карта, D02: 4–6 препятствий r∈[2,6], проходимость не гарантируется. Утилита `cmd/mapgen-preview` — HTML-превью карт для приёмки. Тесты: воспроизводимость, 500 seeds × все инварианты, симметрия, fallback при невыполнимых параметрах, отбраковка плохих карт.
- B05: коллизии `internal/game/collision.go` — пересечение отрезков траектории с кругами (квадратика по сегменту, ветка «старт внутри круга» = мгновенное попадание), самое раннее по ходу; выстрел — луч нулевой толщины, бойцы — круги r=1.0; касание = попадание; ничья 1e-9 → боец важнее препятствия; дружественный огонь, мёртвые и стрелок исключены; максимум одна жертва; порядок объектов не влияет. Тесты: все 9 сценариев тикета + порядок + старт внутри препятствия.
- B04: сборщик траектории `internal/game` — дискретная модель D01: `Y = Y0 + f(t) - f(0)`, направление по стороне (`A` → +x, `B` → -x), шаг 0.5, ≤400 отсчётов, 2 подпробы на интервал; стоп-причины `out_of_field` (точка выхода включается), `discontinuity`, `non_finite`, `max_points`; отказ на старте (`f(0)` не определён) не тратит ход. Тесты: горизонталь, 45°, выходы через верх/низ/края, `x^2` ≡ `x^2+5`, стартовые отказы, обрывы, детерминизм.
- B03: вычислитель формул `internal/expr/eval.go` — безопасный расчёт AST на float64 с семантикой D01: `0^0=1`, отрицательное основание в дробной степени — domain-ошибка, деление на ноль/`ln(≤0)`/`sqrt(<0)`/переполнение — явные ошибки (никогда не `+Inf`/`NaN` в ответе), бюджет операций и отмена через контекст; проверка `f(0)` в B04. Тесты: таблица значений, 12 domain-случаев, недостижимость бюджета через Parse, отмена, детерминизм.
- B02: парсер формул `internal/expr` — лексер и рекурсивный спуск по грамматике контракта (приоритеты, правоассоциативный `^`, унарный минус `-x^2 = -(x^2)`), AST с лимитами (100 символов / 64 узла / глубина 16), позиции ошибок, запрет неявного умножения; тесты: таблица валидных/невалидных формул, лимиты, детерминированный фузз без паник.
- B15: PostgreSQL-слой — Docker Compose (`postgres:17-alpine`, только localhost), миграции goose (`matches`, `match_participants`), типизированные запросы через sqlc v1.31.1 + pgx v5.11.0, команда `cmd/migrate`, разделение `GET /healthz` (liveness) и `GET /readyz` (readiness: ping БД). Интеграционный тест хранилища против настоящего PostgreSQL (`make test-integration`).
- B01: каркас Go-сервиса `graphwar-server` — конфигурация из окружения (`GRAPHWAR_ADDR`, `GRAPHWAR_LOG_LEVEL`), JSON-логи через `slog`, health-эндпоинт `GET /healthz`, корректное завершение по SIGINT/SIGTERM.
- Тесты конфигурации и HTTP-обработчиков (`go test ./...`), команды Makefile: `run`, `test`, `vet`, `fmt`.

### Changed

- Контракт v0.2 — синхронизация с фронтенд-слоем F03: стороны `"A"`/`"B"` (миграция и тесты обновлены; локальную БД пересоздать: `docker compose down -v && make up && make migrate`), фаза `lobby` вместо `waiting`, стоп-причина `hit` (попадание, B05), время в Unix-ms, опциональное `v` в конверте, `turn.opened` несёт `side?`.
