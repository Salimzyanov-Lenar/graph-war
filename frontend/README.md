# Graphwar — frontend

TypeScript + Vite + React + PixiJS. React владеет DOM-интерфейсом, PixiJS — одной игровой сценой. Правила матча, траектории и победа приходят с сервера; клиент их не вычисляет. Задачи — [tasks.md](tasks.md).

## Требования

- Node.js `>=22.12.0` (проверено на 24.13.1)
- npm (версии зависимостей зафиксированы точно, lockfile — `package-lock.json`)

## Команды

```bash
npm install        # установка зависимостей по lockfile
npm run dev        # dev-сервер Vite
npm run typecheck  # tsc --noEmit (Vite типы не проверяет)
npm test           # Vitest, окружение jsdom
npm run build      # production-сборка в dist/
npm run preview    # просмотр production-сборки
```

## Устройство сцены

- `src/scene/mountScene.ts` — адаптер жизненного цикла `Application` из PixiJS: асинхронный `init`, unmount до его завершения, повторный mount, уничтожение приложения и удаление canvas.
- `src/scene/GameCanvas.tsx` — React-компонент: создаёт сцену в `useEffect` и освобождает её в cleanup. Покадровая анимация идёт через ticker Pixi, не через React state.
- `src/field/viewport.ts` — единственный адаптер `worldToScreen`/`screenToWorld`: мир 100×60, x вправо, y вверх; экран в CSS-пикселях, y вниз; сохраняет пропорции, центрирует поле (letterbox), учитывает отступы. DPR обрабатывает Pixi (`autoDensity`).
- `src/field/hitTest.ts` — выбор бойца по курсору в мировых координатах (не зависит от размера окна).
- `src/field/fieldScene.ts` — сцена поля: сетка, оси, границы, препятствия, шесть бойцов. Сторона различается формой (A — круг, B — квадрат), убитый — полупрозрачный с крестом, выбранный стрелок — жёлтое кольцо; наведение — белое кольцо. Всё берётся из `FieldState`, а не из случайных чисел или CSS.
- `src/field/fixtures.ts` — ручная фикстура по контракту `docs/contract.md` v0.1. Реальную карту отдаст сервер (B06).
- `src/contract/` — zod-схемы сообщений сервера (`schemas.ts`), единая точка проверки входа `parseServerMessage` (`parse.ts`: invalid JSON, неподдерживаемая версия, невалидное сообщение) и контрактные фикстуры.
- `src/state/gameState.ts` — чистый reducer: фазы `idle|lobby|active|resolving|finished|aborted`, состояние соединения, правила `streamId`/`seq` (повтор игнорируется, пропуск → `resync`, snapshot заменяет всё). `gameStore.ts` — маленький store, совместимый с `useSyncExternalStore`.
- `src/transport/` — интерфейс `Transport` и `MockTransport`; реальный HTTP/WebSocket-транспорт будет реализовывать тот же интерфейс.
- `src/input/` — логика ввода без DOM: `fireInput.ts` (кто может выбираться, когда выстрел заблокирован, сборка `match.fire`, защита от повтора до подтверждения состоянием), `formulaHelp.ts` (справка; тест сверяет список функций с `docs/contract.md`). Траектория и попадание на клиенте не считаются, предпросмотра линии нет.
- `src/ui/` — `FirePanel` (список своих бойцов кнопками, поле формулы, Enter, справка; текст не стирается при ошибке), `MatchScreen` (выбор мышью по полю и кнопкой делят одно состояние), `useGameState` (`useSyncExternalStore`).
- `src/demo/demoSession.ts` — сценарий вместо сервера для ручной проверки UI: отвечает ошибками `bad_expression`/`domain_error_at_start`, на остальное — фиксированным выстрелом без расчёта попаданий и сменой хода. Заменится реальным транспортом в F04/F05.
- `src/api/rooms.ts` — REST гостевого этапа (`/api/guest`, `/api/rooms…`) с `credentials: 'include'`, ответы проверяются zod; ссылка-приглашение `?room=…&invite=…`. `src/transport/wsTransport.ts` — настоящий `Transport` поверх `WebSocket` (`/ws` текущего origin; в команды добавляется `v: 1`).
- `src/api/health.ts` — `GET /readyz`/`/healthz`, статус сервера на экране входа. `src/ui/OnlineApp.tsx` — имя → создать комнату или войти по ссылке → лобби (игроки, готовность) → матч. `?demo` в адресе включает мок-сессию без сервера.

## Работа с бэкендом

Агенты backend и frontend переписываются через [`docs/agent-sync/`](../docs/agent-sync/README.md): вопросы и ответы по контракту — там, не в чате.

`npm run dev` проксирует `/api` и `/ws` на `127.0.0.1:8080` (единый origin: cookie и проверка Origin). Бэкенд: `docker compose up` в `backend/`, затем `make run`. Бэкенд должен разрешать Origin `http://127.0.0.1:5173`.

Состояние на 2026-10-20: в `main` бэкенда есть health, парсер, вычислитель, хранилище и траектория (B04); контракт v0.2 принял все допущения ниже. Гостя, комнат, `/ws` и выстрела (B08–B12) пока нет, поэтому лобби честно показывает ошибку сервера, а играть можно только в демо (`?demo`).

## Допущения к контракту v0.1 (нужно подтвердить с бэкендом)

Контракт перечисляет события, но не все поля. Схемы в `src/contract/schemas.ts` опираются на следующее:

- в `turn.opened` есть необязательное поле `side` (чей ход) — в контракте указан только `fighterId?`;
- `aborted` приходит как `snapshot` с `phase: "aborted"` (отдельного события в контракте нет);
- команда запроса resync — `stream.resync {streamId}` (в контракте не описана);
- в конверте допускается необязательное `v` (версия протокола); если оно есть и не равно 1, сообщение отвергается;
- `error` не проверяется по `seq`; причины остановки выстрела, коды ошибок и причины завершения принимаются как любые строки (известные значения — `KNOWN_*` в схемах);
- `stopReason: "hit"` в фикстуре — предположение, в контракте попадание не названо как причина остановки.

React Strict Mode включён в `src/main.tsx` и не отключается: тесты проверяют, что после двойного эффекта остаётся один canvas.
